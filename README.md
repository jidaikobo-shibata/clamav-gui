# clamav-gui

ClamAVを利用するデスクトップGUIです。Ubuntu版を開発中で、macOS・Windowsへの対応を予定しています。
ClamAV本体と定義ファイルは同梱せず、端末に導入されているClamAVを利用します。
CiscoまたはClamAVプロジェクトの公式アプリではありません。

## 現在の機能

- 対象フォルダー・除外条件・スケジュールからなる検査プランの保存・編集・複製・削除
- プランごとの手動検査と毎日・毎週（複数曜日を選択可）・毎月・毎時・n分間隔の定期検査
- メインメニューの「検査プランを並べ替え…」から、ドラッグまたは各行メニューの上下移動で表示順を保存。左ペインへ即時反映し、外部メディア検査の位置も保持
- 検査プラン→検査完了日時→ログの閲覧。検出あり・要確認（内訳不明）の日時を太字で強調
- ClamAVオプション20項目とサイズ上限2項目の環境設定
- 実行結果・使用設定の保存と、定期検査のデスクトップ通知

検出ファイルの自動削除・隔離は行いません。管理者権限を使った全体検査は未対応です。
開発版のため、実デスクトップでの通知表示・復帰時の予定実行は継続検証が必要です。

## Ubuntuでの開発

必要なもの：Python 3.10以降、GTK 4、PyGObject、ClamAV、更新済みの定義ファイル。
定期実行はユーザーsystemdを利用します。Ubuntu GNOMEでは通知をクリックするとGUIを起動・前面表示します。定期検査・常駐監視の通知も同じアプリに紐づけます。アプリIDに一致するデスクトップランチャーの導入が必要です。GNOME以外ではnotify-sendによる通常通知へフォールバックします。
Pythonの追加パッケージは不要です。GTKはOSパッケージを利用してください。
リポジトリのルートで起動します。

```bash
/usr/bin/python3 -m clam_gui
```

新規導入時は検査プランが空です。左ペインの＋から追加してください。
フッタには定義ファイルの更新日時と更新設定を開く回転矢印ボタン、ClamAV本体の短いバージョンを小さめの文字で表示します。幅が広いときは横並び、狭いときは縦積みになります。定義の自動更新状態と、UbuntuのAPT管理下のClamAV本体の詳細なバージョン・更新状態はツールチップで確認できます。起動時・5分ごと・再確認ボタン・パッケージ状態確認後にバックグラウンドで確認します。「更新なし（APT情報）」はOSが保持する更新候補との比較結果で、配布情報の鮮度を保証する表示ではありません。配布情報の取得や本体の自動更新は行いません。手動導入版や未対応OSの更新状態は判定しません。

履歴・対象・環境設定はXDG_DATA_HOME配下のclamav-guiへ保存します。
同じアプリの旧版の保存領域（clam-gui）があり、新保存先に履歴DBがない場合は、旧保存領域をそのまま使います。移動・複製・上書きによる移行は行いません。
既存の別アプリから設定・履歴・予定を自動で取り込みません。

結果画面は、結果と次の対応・検査件数と所要時間・検出内容・理由別の警告やエラーの順に表示します。要約は見出し・ラベルで整理し、明細は分類ごとに折りたたみます。開いた分類内はひとつの読み取り専用テキストとして選択・全選択（Ctrl+A）・コピー（Ctrl+C）できます。各分類のコピーアイコンは閉じた状態でも利用でき、画面の先頭100件という表示上限にかかわらず、その分類の保持済み明細を全件コピーします。「結果全体をコピー」には要約と全分類の保持済み明細を含めます。コピーの解析は操作時にバックグラウンドで実施し、元ログの省略についての注意も含めます。検査条件と保持した詳細ログは別の折りたたみで確認でき、詳細ログもコピーできます。分類の件数は保持された明細からの集計で、ClamAVの集計値とは区別します。過去のログの省略部分は復元しません。

結果画面上部の「結果全体をコピー」の横にある「除外設定を編集…」で、保持された報告を直近の親フォルダーごとに整理できます。画面は左右ペインに分け、左にパス入力とログの候補、右に現在のフォルダー除外を表示し、境界の調整と各一覧の独立したスクロールに対応します。開けなかったディレクトリはその場所自体にまとめます。理由の選択欄にはログに存在する分類を並べ、パス入力の部分一致検索と組み合わせて全ページの候補を即時に絞り込みます。ヒット件数は両方に一致するフォルダー数です。その横の「除外される直下」は、全ページのヒットしたフォルダーの直下のファイル・フォルダー等の合計で、配下全体や実際の除外範囲の確定値ではありません。確認中・未確認・一部集計を区別し、1回の集計処理にも時間上限を設けます。複数理由のあるフォルダーは選択理由を含めば表示し、詳細にはほかの理由も残します。一致するパス部分を強調します。入力を消すと全候補へ戻ります。候補のパスを押すと入力欄へ入ります。「追加する」は絶対パスのフォルダーと配下すべてを除外する変更案を作り、該当するログの候補を隠します。除外の「取り消す」で候補が戻ります。旧「除外後に残るフォルダー数」の表示は非表示とし、追加によって除外範囲に入るフォルダー・報告件数は操作後のメッセージに表示します。分類・件数の行を開くと、そのフォルダーの詳細を確認できます。件数は保持されたログに限り、ホーム全体の検査範囲ではありません。保存までは実設定を変更せず、キャンセルで変更案を破棄します。保存前に現在のプラン名・対象・追加/取り消しのフルパスと配下すべてへの影響を確認します。対象全体/範囲外、既知の脅威を含む場所は追加できません。画面を開いている間に対象が変更されたりプランが削除された場合は保存せず、追加/取り消しの差分だけを現在のフォルダー除外へ反映して、他の設定や並行して追加された別の除外を保持します。ファイル単位の除外はこの画面では変更しません。実際のファイルや過去のログは変更せず、除外は次回の検査から反映します。候補には現在の直下のファイル数・フォルダー数を非同期で表示します。配下へ再帰せずリンクを追跡せず、各フォルダーは2万項目または0.25秒で打ち切り、確認できた範囲と読取り不可を区別します。取得結果は画面内で最大1分再利用します。「フォルダーを開く」は入力した既存フォルダーをOSのファイルマネージャーへ渡し、ファイルやURLは開きません。候補は50フォルダーずつ表示し、明細は先頭100件まで、候補行のコピーアイコンはフォルダーのパスだけをコピーします。外部メディア検査はこの画面から変更しません。

Ubuntu/Linuxでは、除外編集画面の「ごみ箱を追加」またはプラン設定の「ごみ箱を除外に追加」から、ホーム側のごみ箱の内容を名前で追加できます。除外一覧は「ごみ箱」と表示し、実パスはツールチップ・確認画面へ残します。既存のパス指定にも名前を適用し、保存形式は実パスのままです。XDG_DATA_HOME（未設定や無効ならホーム内の標準保存先）配下のTrash/filesが対象で、外部メディア側の別のごみ箱は含みません。ごみ箱がまだ作成されていなくても将来の保存場所を登録でき、フォルダーの作成や削除は行いません。対象範囲・既知の検出先の確認はほかの除外と同じで、最後に保存するまで実設定へ反映しません。Windows/macOSのごみ箱は未対応です。

検査出力が大きい場合は、脅威として報告された検出明細を警告や通常出力より優先して保持します。検出明細の保持にも上限があり、全件を保持できない場合は報告件数と保持件数をログに表示します。過去に省略された出力を復元する機能ではありません。
空ファイル（Empty file）と追跡しなかったシンボリックリンク（Symbolic link）の通常出力は、ファイル名の列挙を理由別の件数に集約します。検出・警告・エラーや未知の出力形式はこの集約の対象にしません。
省略済みログに正の検出件数が残り、検出の内訳が不明な記録は「要確認・内訳不明」と表示します。「検出あり」と区別して日時を太字にし、ログ上部にも注意文を添えます。既存の履歴本文や保存済みの検出フラグは書き換えません。
サイズ上限が未設定の新規環境では、1ファイルと展開後の合計をともに256 MiBにします。環境設定は各項目の数値と小さなClamAV標準参考値（100 MiB・400 MiB）だけを表示し、説明文・標準値チェック・サイズ専用の復帰ボタンは置きません。保存済みの数値は維持し、従来の引数省略指定は画面上で256 MiBとして表示します。保存するまで実設定は変更せず、保存時に表示中の数値を明示指定します。「ClamAV標準に戻す」では100 MiB・400 MiBを表示します。
各検査プランの編集画面で「環境設定のサイズ上限を使う」をオフにすると、そのプラン専用の1ファイル・展開後合計の上限を指定できます。既存・新規プランは初期状態では環境設定を継承し、専用値は複製にも引き継ぎます。手動・定期・フォルダー監視で共通適用し、使用値を結果ログへ記録します。

検査オプションを変更したら保存してください。次回の手動・定期検査から反映されます。

```bash
/usr/bin/python3 -m unittest discover -s tests -v
```

GUIの分離検証にはWestonとdbus-run-sessionが必要です。
普段の画面・設定を使わずに検証します。

```bash
/usr/bin/python3 scripts/smoke_gui.py
```

## 定期実行

検査プランの編集画面で予定を設定し、確認後にユーザーsystemd timerを登録します。
GUIを閉じても動作しますが、ログアウト中や電源オフ中の実行は保証しません。
既存のcron等は変更しません。同じ検査の二重登録を避けてください。
開発中はこのチェックアウトの絶対パスでCLIを登録するため、移動時は再登録が必要です。

## UbuntuでClamAVを導入・削除する

「メインメニュー（☰）」→「ClamAVの導入・削除...」から操作します。
導入状態を確認し、インストールまたはアンインストールを選択してください。
APTの変更予定と影響を表示し、確認チェックを入れてから管理者認証へ進みます。

- 対象パッケージはclamav・clamav-daemon・clamav-freshclamです。
- 導入はUbuntuに登録済みのAPT配布元を利用します。通信と空き容量が必要です。
- 既存設定を優先し、パッケージ処理の標準動作によるサービス起動は許可します。
- 初回導入後は定義更新の完了を待ち、「状態を再確認」で状態を確認してください。
- 削除すると、ClamAVを利用する他のアプリ他アプリからもClamAVを使えなくなります。
- removeを使い、purge・autoremoveは行いません。GUIの設定・履歴・予定と実ファイルは残します。
- Ubuntuパッケージ側の処理で定義ファイルは削除されます。再導入後は再ダウンロードが必要です。
- 実行中の検査や他アプリの専用clamdがある場合は処理を開始しません。
- 変更予定が確認時から変わった場合、または無関係な削除が必要な場合は停止します。
- 管理者として実行するのは固定したOSのコマンドです。Pythonやシェルスクリプトをrootで動かしません。
- 認証キャンセルや失敗時は結果と現在の状態を表示します。処理中のAPTは強制終了しません。

48件のテスト、実環境での読み取り・APTシミュレーション、分離Waylandでの模擬実行とキャンセルを確認しました。
実際の削除・再導入、OSの認証画面、初回定義ダウンロードの完了は未検証です。
Ubuntu以外のパッケージ管理には未対応です。


## 定義ファイルの取得・更新

「メインメニュー（☰）」→「ClamAVの管理...」の「今すぐ更新を確認」で実行できます。
インストール成功後にも、自動更新の状態確認と必要な有効化・更新を案内します。

- 既存のFreshClam自動更新サービスを利用し、別のFreshClamを並列起動しません。
- サービスが取得中ならそのまま監視します。待機中ならSIGUSR1で更新を依頼し、停止中なら開始します。
- 必要な場合はOSの管理者認証を求めます。サービスの自動起動設定は変更しません。
- 新しい更新ログと必要な定義ファイルを確認して完了を表示します。過去の成功だけで完了扱いにしません。
- 通信失敗、配信元の制限、サービス停止は表示し、アプリから連続再試行しません。
- 自動更新が有効な場合、「監視を終了」は画面での待機だけを終了し、サービスは継続します。自動更新が無効で今回一時起動した場合は「更新を中断」と表示し、一時サービスも停止します。
- 監視は最大30分です。タイムアウトでもサービスを止めず、完了未確認として案内します。

Ubuntu標準のFreshClam設定と定義保存先が対象です。独自の定義取得設定には未対応です。
更新ログの読取権限がない場合は完了を判定できない旨を表示し、権限設定を自動変更しません。
56テスト、分離Waylandでの模擬更新、実環境ログの読み取りと判定を確認しました。
実ダウンロード・OS認証画面を伴う更新依頼は未検証です。

## 短い間隔のスケジュール

頻度で「毎時」「一定間隔（n分）」も選べます。
毎時は指定した分に実行。一定間隔は1〜1440分で、初回は登録から指定分後、
以後は検査の完了から指定分後に繰り返します。
一定間隔は実行漏れの穴埋めを行わず、スリープ中は間隔の時計が止まります。
開発時は小さなフォルダーと1〜5分程度で試験し、終了後に予定を無効化するか通常の頻度へ戻してください。
既存予定との互換性、timer生成、頻度別UIを確認しています。実時刻の発火は未確認です。

## メール保存ファイルでの検出

mbox形式と確認できた検出ファイルには、メール単位の確認が必要という通知とログを追加します。
件数はメール数ではなく保存ファイル数です。保存ファイル全体を削除・隔離すると正常なメールにも影響するため、メールアプリでの確認を案内します。
メール単位の確認は、使用しているメールアプリで行うよう案内します。

判定は検出ファイル先頭64KiBの形式とヘッダーを読み取る保守的な方式です（最大100候補）。
形式を確認できないものは通常の検出表示になります。メール本文やヘッダー内容はログへ転記しません。
過去の履歴は変更せず、追加後の検査から適用します。メールの削除・隔離は行いません。

## メインメニューとキーボード操作

ヘッダーバー右側の☰から、検査プランの追加、検査設定、ClamAVの管理を開きます。
メニューは区切り線で整理し、検査プラン選択・完了日時・ログの表示はメイン画面に維持しています。
終了はウィンドウの×またはCtrl+Qです。検査・更新などの処理中は終了できません。
F10でメニュー、Ctrl+,で検査設定、Ctrl+?でショートカット一覧を開けます。
一覧はEscapeで閉じられます。アプリ情報もメインメニューから確認できます。

## 対象とスケジュールをまとめて設定

対象の追加・「編集…」で開く「検査プランの設定」にスケジュール欄があります。
定期検査は「対象フォルダーを追加」で複数のフォルダーを登録できます。スケジュールとサイズ上限はプランで共通にし、1回の検査・結果ログにまとめます。除外はどの対象の配下にも指定できますが、対象全体や範囲外は指定できません。対象の重複・親子関係は二重検査を避けるため登録できません。フォルダー監視は引き続き対象1つで、切り替える場合は追加対象を取り消してください。既存の単一対象プランはそのまま使えます。未入力の追加欄は保存対象に含めません。保存・キャンセルは編集画面のヘッダーへ固定し、Enterで保存、Escでキャンセルできます。プラン名やフォルダー指定の明らかな不足がある間は保存を無効にし、欄から移動すると理由を表示します。保存時にフォルダーが見つからない場合などは行番号・直し方を表示し、その欄へフォーカスを移します。
定期検査の有効/無効、頻度、時刻や間隔を設定し、「検査プランを保存」で保存します。
予定変更時は対象と予定の確認が表示され、そこでキャンセルした場合は保存しません。
既存予定も読み込み、予定を変更しなければタイマーを再登録しません。
予定登録に失敗した場合、対象の保存済み/未保存を区別して表示します。保存済みの対象は保持し、同じ画面から再試行できます。
左ペインの各プランの⋮→「編集…」でフォルダー・除外・スケジュールをまとめて設定できます。

## 検査プラン一覧

検査プラン一覧はメイン画面の左ペインに表示します。左上の＋から追加できます。
各行にはプラン名と予定を表示し、ディレクトリのパス・除外条件は編集画面で確認します。
予定は定期検査が無効でも時刻・頻度を残し、「停止中」を添えて表示します。

- 「定期検査」スイッチ：次回以降の予定を切り替えます。有効化時は実行予定を確認します。
  オフにしても、実行中の検査や手動検査・履歴閲覧には影響しません。
- 行末の⋮：今すぐ検査、実行中の検査の中止、編集、複製、削除。
- 検査中はスピナーと経過時間を表示し、中止依頼後は中止処理中と表示します。
  実行していないときは状態行を表示せず、確認できないときはその旨を表示します。
- スイッチ変更中は重複操作を防ぎ、失敗した場合は保存された状態へ表示を戻します。

この版から開始したGUIの手動検査と定期実行CLIは、同じデータ領域のSQLiteで実行状態を共有します。
GUIを開き直しても定期実行中の状態を確認でき、中止は検査側へ協調的に依頼します。
記録にあるPIDへ直接シグナルを送る方式は使いません。
Ubuntuではプロセスの開始識別情報と起動識別情報を照合し、終了・再起動・PID再利用後の記録を実行中と扱いません。
旧版で開始済みの検査や他アプリ・既存cronが直接開始したClamAVの状態は対象外です。
macOS/Windowsでは実行状態の確認方法の移植が必要です。既存のプランID・予定・履歴は維持します。

## 検査を開始できなかった場合

対象フォルダーの消失、ClamAV未導入などで開始できない場合は、手動・定期実行とも理由を画面と履歴に残します。別の全体検査との競合は、検査待ちとして扱います。
手動実行では実行したプランと最新結果を表示します。履歴自体の保存に失敗した場合は、その理由も画面に表示します。
他の検査を自動停止したり、失敗した検査を自動再試行したりはしません。

## メイン画面の左右ペイン

検査プランの管理とログ閲覧をメイン画面へ統合しました。独立した管理ウィンドウとプラン選択ドロップダウンはありません。

- 左：検査プラン一覧。名前・予定・実行状態と定期検査スイッチ、操作用の⋮を表示します。パスは表示しません。
- 右：選んだプランの検査完了日時と、その日時のログを表示します。
- プラン行の本文を選ぶとログが切り替わります。スイッチや⋮の操作では閲覧プランを変更しません。
- 左上の＋で追加し、各行の⋮で編集・複製・削除・手動実行・中止を操作できます。
- ペインの境界をドラッグすると幅を調整できます。プラン一覧・日時一覧・ログはそれぞれスクロールできます。

既存のプランID・予定・履歴は変更しません。実行状態の表示と定期検査スイッチの動作も従来どおりです。

## 定義ファイルの更新日時

メイン画面のログ領域の下に、端末内の定義ファイルが最後に書き換わった日時を表示します。
標準保存先の空でないcvd/cld/cudのうち最新のファイル更新日時を端末の現地時刻で表示し、更新確認だけを行った時刻とは区別します。未取得・確認不能も表示します。
自動更新の状態を表示するボタンから「定義ファイルの更新設定」を開き、既存のFreshClamサービスの設定・手動更新を操作できます。
インストール・削除の操作はメインメニューの「ClamAVの管理」にあります。

## 定義ファイルの自動更新設定（Ubuntu）

メイン画面下部には最終更新日時と「自動更新：有効（稼働中）…」などの状態ボタンを表示します。
状態ボタンから設定画面を開き、自動更新のスイッチ、稼働状態、設定に基づく確認頻度、手動更新を操作できます。
状態の取得はバックグラウンドで行い、外部で変更した状態も定期的に再確認します。

- オン：既存のFreshClamサービスを開始し、OS起動時の自動起動を有効にします。
- オフ：サービスを停止し、自動起動も無効にします。取得中の処理があれば中断します。
- 変更前に他のClamAV連携にも影響することを確認し、必要なOS管理者認証を受けます。アプリ本体は通常ユーザーで動作します。
- 変更後はサービス状態を再読込します。取消・失敗や一部だけ変更された状態を成功扱いにしません。
- 「今すぐ更新を確認」は自動更新の設定を変更しません。自動更新オフで一時起動した場合は、完了・中断・タイムアウト・エラー後に停止へ戻します。
  他の操作で自動更新が有効に変わった場合は、その新しい設定を尊重します。停止を確認できない場合は明示します。
- OS側でマスクされているサービスや独自の起動設定は、アプリが自動解除せず、切替不可として表示します。

新規導入後は現在の自動更新状態を案内します。既存環境の設定をアプリ起動時に勝手に変更しません。
サービスへの設定変更・一時更新は確認操作の後だけ行い、既存の定義ファイルや検査プランを削除しません。

## ClamAVが見つからない場合の起動案内

起動時にclamscanが見つからない場合、インストールを案内します。
「インストールへ進む」でClamAVの管理画面を開き、そこで導入予定を確認してOS認証後に実行します。
案内を開いただけで導入や管理者認証を開始しません。「あとで」を選ぶと履歴や設定を閲覧できます。
同じ起動中は繰り返さず、次回起動時にあらためて確認します。

## フォルダー監視・外部メディア検査

検査プランの追加・編集で「フォルダー監視」を選ぶと、指定したフォルダーの
追加・変更ファイルを検査します。子フォルダーの監視と既存の除外条件も設定できます。
変更が3秒落ち着いてから最大50ファイルをまとめ、ほかの監視系の検査中は待機します。
自動検査の起動間隔は最低15秒、終了後は最低2秒休止します。待機中も変更を集約し、
左ペインに「負荷を抑えて待機中」と表示します。手動の全体検査にはこの休止を適用しません。
一時ダウンロードファイルは完成後の名前変更を待ちます。
初回の監視開始前から存在するファイルは自動検査しません。「今すぐ実行」で全体検査できます。

環境設定の「自動検査・履歴」で外部メディア検査を有効にすると、左ペインに
専用プランが現れます。OSがマウントしたUSBメモリーやデータCD/DVDなど、
GIOがリムーバブルと認識するローカルボリュームを接続時に検査します。
自動マウントや強制取り外しは行いません。画面だけでの監視ではすでに接続済みのものは
「今すぐ検査」で検査します。常駐監視は起動・復帰時の接続済みメディアも検査します。途中の取り外しは検査不完了として記録します。
無効化後も、環境設定から外部メディアの履歴を確認できます。

**環境設定の「自動検査・履歴」でフォルダー監視と外部メディア検査を個別に選択します。**
保存すると、いずれかが有効なら専用のsystemdユーザーサービスを自動登録・起動します。
ログイン中はGUIを閉じても動作し、ログアウト中は停止します。管理者権限は不要です。
両方をオフにすると新しい検査の受付を止め、実行中の検査の完了後に終了します。
フォルダー監視をオフにしても各プランの設定は保持します。
既存の設定は次回の保存からこの自動管理方式に切り替わります。
状態と失敗理由は同じ画面に表示します。障害時にGUIとの二重監視は行いません。
既存のsystemdによる定期検査は従来どおりです。アクセスを遮断する
リアルタイム保護ではありません。
監視準備中の変更やイベント欠落を補うため、定期的な全体検査を併用してください。
監視上限と監視準備の待ち行列はそれぞれ1024フォルダー、準備時の列挙は各フォルダー10000項目、
変更待ちは1000ファイル、メディア待ちは32件です。上限超過は履歴に警告を残します。
正常終了の通知は20秒単位でまとめ、検出・不完了は直ちに通知します。
監視フォルダーが見つからない場合は、そのプランだけ30秒から最大5分間隔で再試行します。
ほかのプランの監視と準備は継続します。上限超過などの監視異常も履歴と通知へ報告し、
同じプランの30秒以内の重複報告は抑制します。

Ubuntuでは検査の子プロセスのCPU優先度を下げ、利用可能なら既存の`ionice`でI/Oをidleクラスにします。
利用できない場合も検査を続け、理由をログへ残します。優先度の効果はOS・ストレージに依存し、
検査のメモリ量やI/O帯域の絶対上限ではありません。大容量の検査で影響がなくなる保証はありません。
設定は再起動せず自動反映します。監視コードの更新は約30秒ごとに確認し、検査の完了後に再起動します。
障害時の再試行には待機時間と回数制限を設けています。

### 履歴の保存上限

同じ設定画面で期間・容量・件数の上限を有効にできます。初期状態は無効です。
提案値は通常履歴90日、検出・不完了365日、ログ本文等256MiB、10000件です。
容量・件数の上限では正常な古い履歴を優先して削除し、それでも超えると
検出・不完了も削除します。有効化や有効中の条件変更では削除の確認が表示されます。
容量は論理的なログ量で、SQLiteファイルはすぐには縮まず空き領域を再利用します。
1回の保存ログは最大2MiB、画面の履歴一覧は最新100件です。
検査中の出力も一定量だけ保持し、一時ログファイルを無制限に増やしません。
大きな出力は一部を省略して不完了として報告します。最初の脅威の検出行は別途保持しますが、
すべての検出行を保存できる保証はありません。履歴の保存に失敗しても、検出結果を残して保存失敗を報告します。

### 常駐監視の再開と制限

常駐監視の初回はファイル情報の比較元を作成し、既存ファイル全体は検査しません。
次回起動・スリープ復帰時は前回から追加・変更されたファイルを検査待ちに追加します。
初回の全体検査は各プランの「今すぐ検査」で行ってください。
監視中でも取りこぼしはあり得るため、定期的な全体検査を併用してください。
電源オフ・スリープ・ログアウト中は検査できません。停止中に作成して削除した
ファイルや、接続して取り外したメディアは後から検査できません。

比較元はアプリのSQLite内に最大100000ファイルのパス・サイズ・更新日時等を保存します。
ファイル本文は保存しません。監視範囲を変更すると比較元を作り直します。
履歴の保存上限とは別の情報です。上限超過時は警告を記録します。
画面だけでの監視の待機キューは引き継ぎません。
自動検査を両方無効にした場合も実行中の検査は続行します。定義更新や定期検査のサービスは変更しません。
コードの配置場所を移動した場合は、新しい場所からアプリを開いて設定を保存してください。

開発検証用の `python3 scripts/smoke_monitor.py` は、一時データ・模擬スキャナーを使って
GUIや実サービスなしの監視・停止・再起動後の変更検査を確認します。
Ubuntuの常駐監視は実装済みですが、macOS/Windowsの常駐起動は未対応です。

ユーザーサービスのセッション連携は、[systemdのgraphical-session.targetの仕様](https://www.freedesktop.org/software/systemd/man/latest/systemd.special.html#graphical-session.target)を参照しています。

## 検査の並行実行と検査待ち

実行枠を「フォルダー全体の検査」と「監視系の検査」に分けています。
前者は手動・定期検査、後者は監視で見つけたファイルと外部メディア検査です。
それぞれ同時に1件、合わせて最大2件のスキャナーを動かします。
監視プランの「今すぐ検査」はフォルダー全体を検査するため、前者を使います。

手動・定期検査は競合しても失敗せず、「検査待ち」として同じ保存先の受付順に進みます。
左ペインで待機を確認でき、各プランの「検査を中止」で待機を取り消せます。
同じプラン・同じ実行枠がすでに実行中または待機中なら、新しい依頼はまとめて追加しません。
登録上限は実行中を含めて同じ枠32件です。監視ファイルは従来どおり集約・再試行します。
定期検査を無効化した場合、待機中の定期検査は取り消します。実行中の検査は続行します。
手動で受け付けた検査は、定期検査の無効化では取り消しません。

全体検査は既存スクリプトと同じユーザーのロックを共有し、監視系は別のロックを使います。
外部のスクリプトがSQLiteの受付順を共有する必要はなく、同じ全体用ロックの解放を待てます。
Thunderbird等、そのロックを使わない別アプリの検査はこの2枠には含めません。

GUIの手動検査・待機はGUIプロセスが管理します。残っている間は通常の終了を防ぎます。
終了するには完了を待つか、各プランの依頼を取り消してください。
定期検査は従来のCLI/ユーザーサービスで動くので、GUIを閉じても待機・実行できます。
待機依頼は、所有プロセスのクラッシュ・ログアウト・電源断を越えて自動再登録しません。
古いプロセスの記録は生存個体を確認して除外し、新しい依頼を妨げないようにします。

監視系の実行枠内では、大容量の外部メディア検査中にフォルダー監視が待つ場合があります。
メディア検査の細分化・途中への短い検査の差し込みは今後の改善です。
更新後はGUIを再起動してください。常駐監視はコード変更を検知し、実行中の処理の完了後に自動で切り替わります。

## 監視の比較情報と未配信通知

今回の更新では監視の比較情報を更新します。更新後の初回は比較元を作り直すため、
更新が反映された後に、監視フォルダーの「今すぐ検査」を一度実施してください。
検査プラン・設定・過去の検査履歴は保持します。

常駐監視の通知はSQLiteへ保存し、順番にOSへ配信します。配信に失敗した場合は
5秒から最大5分の間隔で再試行し、常駐プロセスの再起動後も未配信分を引き継ぎます。
SQLiteの通知キューへ書けない場合も、件数を制限した一時キューで保持して再試行します。
未保存分はアプリのデータ保存先の`notification-retry.json`へ退避し、次回の常駐起動で引き継ぎます。
退避ファイルは通常ユーザー本人だけが読める権限で作成します。退避先にも書けない場合は失敗を報告しますが、
その状態でプロセスが終了するとメモリ内の未保存分を引き継げない可能性があります。
環境設定の常駐監視の状態に、通知待ち件数と再試行中であることを表示します。
個別の未配信通知は256件まで、それを超える分は重要/正常の件数要約として保持します。
配信途中の異常終了では通知が再表示される場合があります。通知表示の許可はOS設定にも従います。


一時的なDB障害で完了済みの実行記録を削除できなかった場合は、所有プロセスが整理を再試行します。
稼働中の別の検査は整理対象にしません。終了処理も段階ごとに実行し、通知保存に失敗しても配送停止とロック解放を試みます。

### 旧管理者設定のあるプラン

以前の「管理者権限が必要」という設定が残るプランは、編集画面で「通常ユーザーで検査する」を選び保存すると通常検査へ変更できます。この表示は対象のアクセス権を自動判定したものではありません。選択後は定期検査も設定できます。管理者権限への昇格や読めない領域の自動除外は行わず、アクセスできない場所は検査不完了として報告します。
