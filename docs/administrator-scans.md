# Ubuntuの管理者権限による手動検査

通常のGUI・定期検査・フォルダー監視は通常ユーザーで実行する。プランの操作メニューの「管理者権限で今すぐ検査…」だけが、対象確認後にpolkitの管理者認証を要求する。保存済みプランの実行権限や定期検査設定は変更しない。

## 導入するもの

- `/usr/libexec/clamav-gui-admin-scan`：管理者所有、0755の独立したPython補助プログラム。
- `/usr/share/polkit-1/actions/com.jidaikobo.ClamAVGui.admin-scan.policy`：管理者所有、0644の専用認証ポリシー。

`/usr/bin/pkexec`、`/usr/bin/clamscan`、`/usr/bin/bwrap`、既存の`libseccomp.so.2`を使用する。GUIをsudoで起動しない。利用者が編集できるプロジェクトのコードを管理者権限で実行しない。補助プログラムは`python3 -I`で起動し、アプリや利用者のPythonモジュールをインポートしない。

初回に操作メニューの「管理者権限で今すぐ検査…」を選ぶと、アプリ内に導入案内を表示する。「導入・更新する」を選ぶと、アプリ同梱の2ファイルだけを含むローカルパッケージ`clamav-gui-admin-helper`を通常ユーザーで準備し、OS所有の`pkexec /usr/bin/dpkg --install`で設置する。Terminalやスクリプトの操作は不要。補助機能の導入認証と、実際の検査開始の認証は別々である。

環境設定の「管理者検査」では導入状態を確認し、必要な更新や削除を実施できる。削除は`pkexec /usr/bin/dpkg --remove clamav-gui-admin-helper`に限定する。ClamAV本体、検査プラン、履歴、通常の定期検査・監視設定は変更しない。実行中の検査を止める操作ではない。

ローカルパッケージには維持用スクリプト・トリガー・常駐サービスを含めない。dpkg標準のパッケージ管理情報は更新される。既存のpython3・pkexec・bubblewrap・libseccomp2に依存する。不足時はエラーとして表示し、任意のパッケージを勝手に追加しない。認証をキャンセルすると検査には進まない。パッケージ変更が始まった後は、タイムアウトやGUIの終了で途中のdpkgを強制終了しない。

専用の検査アクションは`auth_admin`を使用し、認証の一時保持は指定しない。導入・削除はOS標準のpkexec認証を使う。組織・OSの追加ルールにより認証方法や要求条件が変わることはある。

補助プログラムや認証設定を更新した場合は、次回の検査操作で導入・更新へ案内する。GUIは導入先の所有者・書き込み権限・シンボリックリンク・現在のソースとの一致を確認する。同名の別パッケージやパッケージ管理外の既存ファイルは自動上書き・削除しない。利用者がファイルを書き換えられる権限にはしない。

開発者が設置内容を確認する予備手段として、`scripts/prepare_admin_helper.py`も残す。手動設置は通常の利用フローではなく、パッケージ管理外のファイルはアプリの自動更新・削除の対象にしない。

## 実行上の制限

- 固定されたClamAVと許可済み検査オプションだけを受け付ける。シェル、任意コマンド、削除・隔離・任意のDBやログ保存先の指定は受け付けない。
- 対象・除外・オプションは上限4096バイトのJSONで渡す。設定が大きすぎる場合はプランを分ける。
- `/proc`・`/sys`・`/dev`・`/run`は対象に指定できず、配下にあっても除外する。別ファイルシステムへ自動で進まない。検査したい別ファイルシステムは明示的な対象として追加する。
- bubblewrapでホストのファイルシステムを読み取り専用にし、実デバイスを公開しない。専用の一時フォルダーのみ書き込み可能にする。ネットワーク/PID名前空間を分離し、読み取り用の能力以外は落とす。libseccompでソケット作成・接続・ptrace・mount等を禁止する。隔離に失敗した場合は制限なしでの再実行をしない。
- 実行中は`/run/clamav-gui-admin-scan.lock`を管理者所有で使用し、管理者検査同士の競合を拒否する。通常の全体検査の実行待ち・ロックも継続利用する。
- `/var/tmp`に管理者所有の専用一時領域を作り、終了時に片付ける。GUIの中止要求・通信切断・終了を受けて補助プログラムが検査を停止する。
- 検査結果は通常権限のGUIへ標準出力で返す。利用者のSQLiteや出力先を管理者プロセスから開かない。GUI側で管理者手動検査と分かる記録を残し、通常の結果表示・通知を使う。
- 管理者であっても暗号化、サイズ上限、セキュリティ機構等によって検査できない内容はある。システム侵害がないことを証明する機能ではない。

## 確認状況

要求の検証、許可されない引数の拒否、フィルター生成、通信切断時の停止、認証キャンセルの履歴、GUIの確認・開始処理を管理者権限なしでテストする。導入/削除処理を模擬化した分離GUI検証と、実際のローカルパッケージ生成・内容確認を行う。実際のpolkit認証、rootでの読み取り、bubblewrapの隔離動作は、利用者がアプリ内で導入を承認した後に実機で確認する。初回は小さな専用テストフォルダーを使う。
